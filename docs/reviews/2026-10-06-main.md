## Minor
### 🟡 Possible referral code collision, `src/app/modules/campaign/campaign.service.ts:102`
**Problem**: The referral code is generated using a 6-character random string (`Math.random().toString(36).substring(2, 8).toUpperCase()`) and constrained by a unique index globally.
**Why it matters**: As the database grows, the birthday paradox makes a collision more likely. When a collision occurs, `CampaignParticipant.create` will throw an unhandled Mongo E11000 duplicate key error, resulting in a 500 Internal Server Error for the user.
**Suggested fix**: Add a retry loop for code generation on collision (e.g., attempt generation 3 times before failing) or use a more collision-resistant generator like `nanoid`.

### 🟡 Missing pagination on active campaigns list, `src/app/modules/campaign/campaign.service.ts:68`
**Problem**: `getActiveCampaigns` returns all matching active campaigns without limits or pagination.
**Why it matters**: When the platform scales to thousands of active campaigns, this query will become slow and consume excessive memory on both the server and client.
**Suggested fix**: Implement standard cursor-based or offset-based pagination (`limit` and `page`) for the `find` query.

## Nits

- ⚪ `src/app/modules/campaign/campaign.service.ts:10`, the `payload` parameter is typed as `any`. It would be safer to define an interface or use Zod inference to type the input payload for the service methods.
